# Addendum: AI Payment Refund Agent

Mechanism-level detail relocated from `prd.md` during the structure/prose polish pass — tech choices, not capability requirements. These are proposed defaults for the architecture stage to confirm or replace, not settled decisions.

## Confidence Score computation (relates to Glossary / FR-6)

Confidence Score is produced by an LLM-as-judge self-rating step: after each Trajectory decision point, the agent is prompted to rate its own certainty against a fixed rubric (data completeness, policy-match clarity, ambiguity signals), normalized to 0–1.

## FR-6 minimal MVP policy rule set

Before FR-2 (RAG-grounded Policy) ships, policy-compliance for auto-approval is evaluated via a minimal hardcoded rule set:
- Order exists and is in a completed state
- Request is within the return window
- Requested amount does not exceed the original order amount

Superseded entirely once FR-2 ships.

## FR-4 Idempotency Key derivation

Idempotency Key = a hash or composite of Order ID + Refund Request ID (or other request-specific fields) — never Order ID alone, so distinct legitimate requests against the same Order don't collide on Stripe's idempotency semantics.

## FR-9 Golden Dataset generation methodology

Golden Dataset entries are generated by actually running the agent against curated synthetic scenarios during development — not hand-authored expected-output pairs, and never real customer data (see PRD Privacy constraints).
